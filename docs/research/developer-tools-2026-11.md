# Developer tools and reusable product patterns

Research date: 14 November 2026. Status: recommendations, not installed dependencies.

This inventory covers Context7 and all 31 names in the request. It separates tools for developing LocalMind from software that might become part of LocalMind. Installing a coding skill does not add that skill's capabilities to the shipped desktop app or improve a model's weights.

Evidence is the linked projects' current READMEs and installation documentation, inspected during this review. “Documented” means the author provides that integration; it does not mean we installed it or verified it on this Windows computer. These are compatibility and scope assessments, not security audits or independent reproductions of advertised benchmark results. Check the selected release, dependencies, and license before adopting code.

## How compatibility works

- **Native integration:** the repository documents a Codex plugin, installer, or adapter. Hook behavior can still differ from Claude Code.
- **Portable skill:** instructions can be used by a skill-aware agent, but script paths, shell commands, tools, and permissions must match the host.
- **MCP:** a separate server exposes tools. Codex can connect through a supported transport; LocalMind would need its own compatible client, authentication, tool controls, and tests.
- **CLI or library:** callable from development tools, or integrated deliberately into the app. It is not automatically a Codex plugin.
- **Catalog/reference:** useful for discovery. Entries require individual review; there is no meaningful “install the whole list” operation.

## Recommended first adoption batch

1. Keep the existing GitHub connection. Add no second GitHub identity or write path merely to gain another tool.
2. Pilot Context7 for documentation lookup and Serena **or** Repomix for source exploration. Measure whether they reduce missed dependencies and unnecessary file reads.
3. Use a small selection of Matt Pocock's skills or Superpowers for engineering workflow, rather than combining multiple comprehensive frameworks.
4. Use Playwright-based testing for web UI journeys and retain native Tauri checks for clipboard, mini chat, startup, and updates.
5. Keep unslop for documentation. Treat Taste Skill/UI UX Pro Max as review aids and validate design with real users.

No tools were installed, credentials changed, hooks enabled, models downloaded, or third-party code executed for this inventory. A later installation should pin a reviewed version, state the files/settings it changes, test one workflow, and provide removal instructions.

## Product ideas worth testing separately

- **Small context index, details on demand:** test Claude-Mem's retrieval pattern against cross-chat contamination and correction handling.
- **Visible provider decisions:** use Router/CC Switch as UI references for showing model, destination, availability, and estimated cost before a cloud request.
- **Durable tasks:** borrow explicit dependencies and run states from Beads/Vibe Kanban, while keeping user tasks in LocalMind's own store.
- **Recoverable compression:** evaluate Headroom on verbose tool output with retained originals and exact source references. Reject it if task accuracy falls.
- **Browser and GitHub connectors:** start with read-only tasks, then add separately approved writes. A model's ability to emit a tool call is not authorization to perform it.

These hypotheses should be compared with the current implementation on held-out tasks. None establishes that a local model will match a frontier model, and none is a reason to replace the existing stack wholesale.
