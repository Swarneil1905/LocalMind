# LocalMind 1.0.0

Answers you can check, memory you can see, and a safer shell around both.

1.0.0 means the core loop is ready to rely on: install, pick a model, chat, follow up, search your files, and update. It does not mean the model is never wrong. Voice, media generation and connected apps are still pilots (see Limits).

## Changes since 0.9.0

**Answers**
- Web answers cite sources inline and show source cards with publish dates. News headlines are ranked for relevance, and the search is date-aware.
- When Web finds nothing current, LocalMind shows a fixed notice and answers from the model's own knowledge under a policy that forbids stating current facts. It no longer pretends.
- Follow-ups about the last answer, such as "what is the source for that?", no longer trigger a new search.
- Answers take the shape of the question: numbered steps for how-to, short bullets for news and finance.
- If Web is off and the question needs it, one button turns it on and retries. If a cloud answer fails, one button retries the same question on your local model.
- The model stays loaded for 30 minutes after your last message, which removes the reload pause between messages.

**Memory**
- Memories are saved only when you actually stated the fact, not when the chat merely discussed it.
- Answers list "Memories used" so you can see what shaped them.
- A daily tidy merges exact repeats and removes records that only describe the chat. It never rewrites a memory or calls a model, and it saves a backup first.
- Memory context has a fixed size budget, so a long memory list cannot crowd out your question.

**Chat and Knowledge**
- Chats name themselves, and rename as the conversation develops. Follow-up questions are suggested.
- Knowledge shows when the embedding model is missing and offers a one-click download.
- Knowledge, Memory, Settings and the model picker are restyled. The model picker uses plain names: Fast, Smart, Best.
- DeepSeek is available as an optional cloud provider. Chart legends and series colours are clearer.

**Security and reliability**
- Fetched web pages are checked again after the connection opens, closing a DNS-rebinding gap.
- Every identifier the desktop app passes to the local service is validated before it becomes part of a request path. Cloud provider actions have an allow-list test.
- Release builds apply a content security policy.
- FastAPI 0.163.1 and patched Rust dependencies (`h2`, `rustls`, `rustls-webpki`, `tokio` and others).
- Migration of older data logs failures instead of hiding them.

## Updating

0.9.0 installations can use **Settings → Updates** or the update banner. Finish active responses and save unsent drafts first. Chat models download separately, and updating does not replace model weights or train the model.

## Limits

- Local model quality still varies. An 8B model can state a wrong fact confidently, and Web search can return no sufficiently recent, dated evidence. Check sources for anything that matters.
- The first message after the model has been idle is slow while it loads.
- Voice (Windows x64 English pilot), media generation and connected apps keep their documented pilot and consent requirements. Local image generation stays disabled unless its quality gate passes. Paid provider calls need your own account and explicit approval.
- Windows Authenticode signing and Apple notarization are not configured, so your OS may show a security prompt. Updater bundles are signed with the existing LocalMind key.
- The release content security policy has been checked in development only. Report anything that fails to load, such as voice or diagram export, in a packaged build.
- `zip` 4.6.1, used by the updater, carries an open advisory. It stays pinned because the updater's signature check depends on it.
- Profile databases rely on your OS account permissions and are not encrypted by LocalMind.
